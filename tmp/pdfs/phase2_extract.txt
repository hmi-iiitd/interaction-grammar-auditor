PRD: NAO-Based HRI Experiment Package
for Interaction Contract Auditor
1. Objective
The goal of this phase is to convert the current Interaction Contract Auditor system into a
complete NAO-based HRI experimental package.
The system already supports:
● natural-language contract authoring,
● scenario understanding,
● clarification,
● contract preview,
● validation and mapping,
● contract locking,
● trace audit,
● UNSAT/SAT report generation,
● timeline and counterexample visualization.
The next phase must produce a reproducible NAO dataset, baseline comparisons, and a
pilot-ready HRI evaluation protocol.
This phase is not about adding more UI features. It is about producing experimental evidence.
2. Core Research Goal
We want to show that non-technical HRI researchers can define intended interaction
expectations as contracts, lock those contracts before audit, and use the resulting audit reports
to diagnose NAO interaction failures more clearly and reproducibly.
The core claim to support is:
Interaction contracts make HRI breakdowns auditable by identifying what
coordination obligation failed, when it failed, where it failed, and what trace
3. Scope
evidence supports the diagnosis.

5.2 Pass Conditions
A scenario passes authoring requirements only if:
1. It starts from natural-language description.
2. Candidate obligations are extracted.
3. Missing timing/repair/interruption details are clarified.
4. Contract preview shows plain language, grammar notation, JSON, and provenance.
5. Schema validation passes.
6. Semantic validation passes.
7. Event mapping passes or is explicitly not required.

===== PAGE 7 =====
8. Contract is locked before audit.

5.3 Fail Conditions
A scenario is invalid if:
1. Audit is run before contract locking.
2. Contract is changed after audit without a new version.
3. Contract hash is missing.
4. Clarification answers are missing.
5. Plain-language contract and JSON disagree.
6. Event mapping is hidden or unresolved.

13. Go / No-Go Criteria for HRI Paper
Proceed toward paper writing only if:
1. All 12 NAO scenarios are complete.
2. At least 10/12 audit outputs match ground truth.
3. All UNSAT cases produce usable counterexamples.
4. Reproducibility passes.
5. Baseline comparison is complete.
6. Pilot users can complete authoring and diagnosis tasks.

===== PAGE 23 =====
7. The system does not require manual JSON editing during the normal workflow.
8. The paper has at least 4 strong case examples.
Do not proceed if:
1. contracts are being manually adjusted after audit,
2. traces are inconsistent,
3. counterexamples are unclear,
4. participants cannot understand the workflow,
5. outputs are not reproducible.
